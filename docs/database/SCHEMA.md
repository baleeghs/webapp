# Database

Postgres, accessed with sqlx. (Without `DATABASE_URL` the server uses in-memory storage instead;
see the README.) Migrations live in [server/migrations](../../server/migrations),
are embedded in the binary and run at startup (or with `app-server migrate`).

## Tables

| Table | Owner (feature) | Notes |
| --- | --- | --- |
| `notes` | notes | Example feature. `id` UUIDv7, `title` 1–200 chars, `body` ≤ 10 000 chars |

Keep this table current when adding migrations.

## Conventions

- **Primary keys**: `uuid`, generated by the application as UUIDv7 (time-ordered).
- **Time**: `timestamptz` only, written as UTC. Every table has `created_at` and `updated_at`.
- **Constraints in the database too**: `NOT NULL`, `CHECK`, `UNIQUE` and foreign keys back up the
  service-layer validation, so bad data cannot get in by another path.
- **Names**: plural snake_case tables, snake_case columns, indexes `<table>_<columns>_idx`.
- **Queries**: written in the feature's repository (`app-db/src/<feature>.rs`), selecting
  explicit columns into a `FromRow` struct that converts to the domain type.

## Migrations

```sh
make migration name=add_users   # creates <timestamp>_add_users.up.sql and .down.sql
make migrate                      # applies pending migrations to DATABASE_URL
```

- Every migration has a working `.down.sql` (CI checks that the pair exists).
- Never edit a migration that has been applied anywhere shared; add a new one.
- Write migrations that are safe on a live database: add nullable columns or columns with
  defaults, create indexes `CONCURRENTLY` in their own migration (sqlx: add
  `-- no-transaction` at the top), backfill in batches, and drop things only after the code that
  used them is gone.

## Tests

Repository tests in `server/crates/app-db/tests/` use `#[sqlx::test]`, which creates a fresh
database per test and applies all migrations. They are `#[ignore]`d by default:

```sh
make db-up && make test-db
```

CI runs them on every push against a Postgres service.
